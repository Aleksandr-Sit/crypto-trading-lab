## Полнота и существенные ограничения

1. Число исходов в stdout и агрегатах равно числу уникальных счетов каждого
   старого снимка. Но сохранённый portfolios.jsonl покрывает только 124/200,
   971/1446 и 987/1428 счетов. Ответы остальных скрипт получал в память через API
   и не записывал. Поэтому полный результат независимо пересчитать из архива
   невозможно. В сохранённых 3149 кривых дубликатов адресов нет; в проверенных
   рядах снимков нарушений строгого порядка времени не найдено. Частичную
   выборку не подменяем полной и по ней рейтинг заново не оцениваем.
2. **Начало измерения загрязнено периодом ДО заморозки.** `forward_return`
   берёт последнюю точку allTime не позже 00:00 UTC даты снимка, а не сохранённую
   прибыль в момент фактической заморозки. У доступных счетов точка pnl отстаёт
   от этого полуночного рубежа на 2.00–9.09 суток для 26.09 и до 7.09 суток
   для 01.10 (12.09: 2.01–9.09). Сам рейтинг замораживался ещё позднее полуночи.
   Расчёт включает часть уже известной истории; называть его строго будущим
   результатом нельзя. Точки конца доступного кэша — 01.11 04:10–04:59 UTC,
   точного общего времени оценки также нет.
3. Снимок 12.09 — только топ-200: сравнение элиты с элитой, не полного рейтинга.
   Поздние снимки полные. Возраст 31–50 дней пока меньше заявленных 3–6 месяцев.
4. Капитал в знаменателе тоже берётся из редкой старой точки; пополнения после
   неё меняют масштаб прибыли относительно исходного капитала. Это не полная
   доходность инвестора с учётом потоков и не модель комиссий/задержки копии.

## Решение и следующий шаг

Устойчивого преимущества даже опубликованные агрегаты не показывают. При этом
из-за загрязнённого начала они не доказывают ни наличие, ни окончательное
отсутствие будущего навыка. Ноябрьский контроль **разобран с ограничениями**;
исследование копитрейда не объявляется завершённым чистым форвардом.

Для будущей отдельной версии протокола нужны исходные pnl/капитал и точное время
заморозки, архив каждого ответа, индивидуальные исходы и контроль общего конца.
Прошлую точную базу из текущих редких кривых восстановить нельзя. В этой сессии
крон, сборщик, снимки и работающие наблюдения не менялись. Следующий штатный
прогон — 01.12; без исправления базы длительность сама по себе изъян не устраняет.
