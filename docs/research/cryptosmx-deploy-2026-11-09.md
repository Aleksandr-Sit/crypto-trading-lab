# Точечная выкладка CryptosMX

Исправлены `scripts/crash-paper-deploy.sh` и протокол управления в
`scripts/crash_bounce_control.py`. Работающие боты в этой сессии не обновлялись.

## Порядок

1. Захватывается блокировка от параллельной выкладки. Проверяются наличие обоих
   контейнеров, поддержка drain protocol 1 и свободное место.
2. Чистый серверный checkout обновляется до закреплённого upstream-коммита через
   fetch + fast-forward merge. Изменение общей папки config/ блокируется до merge:
   она подключена в другие работающие сервисы и может повлиять на них без перезапуска.
3. Собираются только crash-paper и crash-forward, пока старые процессы работают.
4. Бумажный бот подтверждает запрет новых входов на всех шести счетах и зеркале.
   Существующие позиции продолжают закрываться по обычным правилам. Подтверждение
   готовности выдаётся из того же event loop только при отсутствии всех позиций.
   Сборщик архива завершает текущее задание и подтверждает паузу между заданиями.
5. После получения готовности пауза фиксируется отдельной командой commit.
   Оба процесса должны подтвердить фиксацию. Такая пауза не истечёт сама во время
   задержки Docker, поэтому новый вход между проверкой и остановкой исключён.
6. Останавливаются и пересоздаются только два указанных сервиса. Используются
   --no-deps, --no-build, --pull never и --force-recreate. Общий update.sh не вызывается.
7. Проверяются новые ID контейнеров, версия кода, здоровье потока paper и запуск
   архивного процесса. Последняя стартовая запись paper сравнивается со снимком
   счетов при паузе: equity, withdrawn, min_bal и дневные счётчики должны совпасть,
   open_lost обязан быть равен нулю. Сравнивается именно стартовый снимок, поэтому
   новые сделки после запуска не мешают проверке восстановления.

worker, bot, web, forward-report, migrate и db не входят в команды build/stop/up.
Сборка всё равно использует ресурсы общего сервера, но не пересоздаёт соседние сервисы.
Параметры опыта, счета, журналы и начало окна не обнуляются.

## Ошибки и восстановление

До фиксации пауза имеет срок действия 120 секунд и продлевается скриптом.
Если скрипт исчезнет, процессы возобновят работу после истечения срока.
При обычном выходе с ошибкой, SIGINT или SIGTERM обработчик отменяет свои паузы.
Чужой token не может отменить или перехватить паузу.

После фиксации автоматического истечения нет: это необходимо, чтобы поздняя команда
остановки не пришлась на уже возобновившиеся входы. При SIGKILL/потере хоста после
фиксации оператор должен проверить состояние контейнеров и либо завершить выкладку,
либо отменить паузу с её token через control cancel. Обычный EXIT-cleanup снимает
фиксацию, если старые контейнеры ещё доступны. После частичной ошибки stop/up нужно
проверить оба сервиса; автоматического слепого отката нет, поскольку новая версия
уже могла открыть позиции.

Административные паузы записываются в журнал как drain и отдельно учитываются в
диагностике качества; сигналы во время запрета входов исключаются из сверки К3
с явной причиной excluded_deployment_pause. Их не маскируют как ошибки стратегии.

## Первый переход со старой версии

Старая работающая версия не поддерживает подтверждённую паузу. Проверка новой
версии скрипта на сервере с --dry-run завершилась отказом:

`REFUSED: running crash-paper lacks drain protocol 1; no safe legacy fallback.`

Этот отказ происходит до обновления checkout, сборки, запросов паузы и остановки.
Файл control, просто скопированный в старый контейнер, не решает проблему: старый
процесс не подтвердит запрос. Нужен отдельный план первого перехода с явно заданной
границей наблюдения/переносом состояния. Старый способ «поймать ноль и перезапустить»
не используется как запасной вариант.

Добавлен отдельный `scripts/crash_bootstrap_deploy.py` для первого перехода именно
с проверенной версии e446abebae12efd9776784926c8e63482a474e47 на Linux x86_64.
Он сверяет исходники работающих контейнеров, замораживает оба контейнера, проверяет
ожидание событий главным потоком paper и сон между заданиями у forward. Проверяются
отсутствие дочерних заданий, целостные JSONL и ноль незакрытых записанных исполнений.
Если условия не выполнены, контейнеры размораживаются для продолжения работы.
Это исключает остановку Python посреди незавершённой записи исполнения.

При успешной проверке создаются резервная копия журналов/архива и снимок всех счетов
с SHA256 журналов. В замороженном состоянии каждому процессу контейнеров направляется
SIGKILL, затем контейнеры размораживаются только для завершения — пользовательский код
старого бота больше не исполняется. Автоматический restart старых контейнеров заранее
отключается. Новая версия запускается только для двух сервисов и обязана восстановить
те же счета. Для остальных контейнеров сравниваются ID и StartedAt. Старые образы
сохраняются отдельными тегами для управляемого восстановления.

Bootstrap не является неявным запасным режимом обычного деплоя и требует явных
`--commit` и `--evidence`. Реальные ордера этот переход не создаёт.
