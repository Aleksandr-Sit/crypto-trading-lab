## Что проверяется и чего эта проверка дать не может

Таблица — самоотчёт: цен входа, стопа и цели нет, поэтому ни плюс автора, ни правило из неё
проверить нельзя. Согласованность — необходимое условие доверия, не достаточное: аккуратно
ведённый журнал может быть отобран задним числом. Возможны два исхода:

* **«не согласована»** — в таблице есть противоречия сверх опечаток: журналу не доверять;
* **«согласована»** — противоречий сверх опечаток нет; это НЕ `passed` и не повод что-то
  брать в бота. Дальнейшей работы по SANCHO в обоих случаях не будет (платная группа —
  за пределами объёма, решение владельца 03.10).

## Правила проверки (объявлены ДО прогона)

Строка-сделка — строка с непустой парой ниже шапки. Каждая проверка печатает число нарушений
и сами строки (номер строки листа), чтобы опечатку можно было отличить от системы.

**П1. Шапка ↔ строки `full`** (арифметика итогов). Определения объявлены заранее; проверка
пройдена, если для каждой величины совпадает хотя бы одно из них, и печатается, какое:
* «Всего» — (а) все строки; (б) без Активна/Ожидание; (в) без Активна/Ожидание/Неактивна.
  Допуск — точно.
* WR — ✓ / (✓ + ✗) или ✓ / (✓ + ✗ + б/у), %. Допуск ±0.05 п.
* Результат — сумма колонки «Результат, %». Допуск ±0.5 п.
* RR — среднее непустых RR: по всем строкам или только по ✓. Допуск ±0.01.
* Депозит — $10 000 × Π(1 + r/100) по строкам в порядке листа. Допуск ±0.5%.

**П2. Строки ↔ легенда.** Нарушение — строка, где:
* ✓, а результат ≤ 0 или пуст; ✗, а результат ≥ 0, пуст или < −1.1 × риск;
* б/у, а результат вне [−0.1; 0.3] (пустой — допустим); б/о, а результат не пуст;
* ✓ с результатом больше RR × риск + 0.01 (фактическое не может превысить объявленное RR);
* исход и статус не сходятся: ✓/✗/б/у — только «Закрыта», б/о — только «Неактивна»;
  у «Активна»/«Ожидание» — исход ✓/пусто допустим (по `active`: незакрытая в плюсе — ✓);
* депозит строки ≠ депозит прошлой строки × (1 + r/100) больше чем на $2 (строки без
  результата депозит не меняют).
Пройдено — нарушений ≤ 1% строк. Отдельно (справочно) — число ✓ с результатом в (0; 0.3]:
пересечение с определением б/у.

**П3. «Полная история» ↔ сезоны.** Ключ строки — пара, дата, направление, ссылка «Пост №1».
* Каждая строка сезонов есть в `full` и наоборот (кроме «Активна»/«Ожидание», которых в
  сезоне может ещё не быть), поля RR, исход, результат совпадают.
* Сумма результатов по шапкам сезонов = результат шапки `full` (±0.5 п.); депозит на старте
  сезона k = депозиту на конце сезона k−1 (±$2), если сезоны ведутся нарастающим счётом.
* Шапка каждого сезона ↔ его строки — по правилам П1.
Пройдено — совпадает ≥ 99% строк и все суммы в допуске.

**П4. Хронология постов** (главная проверка на «вписано задним числом»). Отдельно для
закрытой группы и открытого канала, только «Пост №1» (вход):
* строки упорядочиваются по (дата, порядок в листе); нарушение — строка вне самой длинной
  неубывающей подпоследовательности номеров «Пост №1» (минимальное число строк, которое надо
  убрать, чтобы номера шли вместе с датами);
* внутри сделки номера постов одного канала строго растут (№1 < №2 < …);
* справочно: строки с одинаковыми (пара, дата, направление); один «Пост №1» у разных сделок;
  порядок строк листа против порядка дат.
Пройдено — нарушений хронологии ≤ 2% строк и порядка внутри сделки ≤ 1%.

**П5 (справочно, не в вердикт). Даты открытых постов.** Для ссылок на `t.me/SANCHO_DT/N` —
дата публикации со страницы поста (открытая веб-версия, без входа). Нарушение: «Пост №1»
опубликован позже даты сделки больше чем на сутки или «Пост №k>1» — раньше даты сделки. Это
единственные метки времени не от автора; в вердикт не идут, так как выходят за объём.

**П6 (справочно). Что таблица говорит о себе, если ей верить.** Среднее на сделку и
кластерная ошибка по месяцам (`block_stats`, как в прошлых пунктах); по сезонам; доля
б/о среди всех сигналов; сумма % против нарастающего депозита (+208% в шапке — сумма или
сложный процент); распределение результатов ✓. Это описание самоотчёта, а не проверка плюса.

**Вердикт.** «Согласована» — пройдены П1–П4 все; иначе «не согласована» со списком
нарушенных пунктов. Порог «опечатки» — те самые 1–2% выше; нарушения ниже порога всё равно
печатаются.
