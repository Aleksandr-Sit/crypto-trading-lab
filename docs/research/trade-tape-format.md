# Лента для коротких стратегий

Общий замер умеет потоковый replay **рыночных заявок одного инструмента CEX-спота**
с котировкой USD/USDT/USDC. Правила получают `Event(kind="trade", ts=...,
payload={sequence, ts, price, qty, side, venue, instrument})` через `on_event`.
`side` — сторона АГРЕССОРА, не маркетмейкера. Обязательный контракт стратегии
по-прежнему содержит `manifest`, `on_bar` и `on_event`; свечи в этом режиме не подаются.

В параметрах карточки/реестра:

```yaml
execution_data: trades
execution_latency_ms: 250
max_participation: 0.1
```

`execution_data: trades` запрещает незаметный откат к свечам при отсутствии ленты.
Параметры задержки и участия берутся из эффективного манифеста стратегии. Нулевая
задержка запрещена. Участие — в (0, 1]. При явном `--tape` replay можно запустить
и без декларации `execution_data`; выбор режима сохраняется в параметрах замера.

Запуск через общий журнал попыток:

```text
lab measure run <strategy-id> --mode backtest --tape /path/to/trades.jsonl
```

Окно берётся из заголовка вместо `--days`. `paper`, `forward` и `micro` не
заменяются replay: они используют соответствующие сделки журнала. Walk-forward
в режиме ленты пока не поддержан и получает `incomplete`.

## JSONL

Первая строка — заголовок. Следующие строки — ВСЕ сделки объявленного инструмента
и окна, включая обе стороны. Нельзя отфильтровать ленту по сигналам или стороне.
Все даты содержат часовой пояс. Цены и объёмы рекомендуется писать строками
Decimal. Числовой `sequence` — исходный непрерывный номер сделки/агрегата источника;
нельзя перенумеровывать отфильтрованную ленту, скрывая пропуски.

```jsonl
{"format":"lab-trades/v1","venue":"bybit","instrument":"BTC/USDT","covered_from":"2026-01-01T00:00:00Z","covered_to":"2026-01-01T00:00:10Z","first_sequence":1000,"last_sequence":1001}
{"sequence":1000,"ts":"2026-01-01T00:00:01Z","price":"90000","qty":"0.1","side":"sell"}
{"sequence":1001,"ts":"2026-01-01T00:00:02Z","price":"90001","qty":"0.2","side":"buy"}
```

Границы окна — `[covered_from, covered_to)`. Прямой `core.measure.run(...,
tape_path=..., window=...)` требует точного совпадения окна с заголовком.
Проверяются площадка, инструмент, первый/последний номера, непрерывность номеров,
неубывание времени, принадлежность окну, положительные цена/объём и сторона.
Повтор, разрыв, обрезанный хвост, пустая лента и невалидная строка дают
`incomplete` без частичных метрик. Файл читается потоково; в памяти не копится
список сделок ленты. Использованные строки входят в отпечаток данных.

## Модель исполнения и границы

- Решение принимается после обработки текущей сделки. `decided_at` должно
  совпадать с временем полученного события; инструмент тоже должен совпадать.
- Покупка исполняется на следующем подходящем print покупателя-агрессора,
  продажа — продавца, не раньше `decided_at + latency` и строго до истечения TTL.
  Положительная задержка запрещает использование другого print того же времени.
- Все заявки делят `qty × max_participation` каждого print в порядке подачи.
  Остатки ожидают следующих подходящих print до TTL. Покупки ограничены
  свободным капиталом с комиссией, продажи — фактическими лотами. Шорт не открывается.
- Цена print уже содержит свою сторону спреда; отдельно начисляется taker-комиссия
  из общей модели. Повторный модельный спред не добавляется. FIFO и издержки
  закрытых лотов общие с `PaperEngine`.
- Просадка оценивается на каждом print, с открытыми лотами и комиссиями. После
  пробоя стопа покупки отменяются и блокируются, закрывающие продажи остаются.
  Дневной стоп использует закрытый P&L, как существующий симулятор.
- Открытый P&L — по последнему print, а не по исполнимому bid. Он входит в общий
  результат, но не в закрытый EV/его интервал/стресс издержек.

Это историческая аппроксимация ликвидности по принтам, не реконструкция стакана,
очереди или гарантированного исполнения собственной заявки. Фактические задержки,
impact и очередь могут быть хуже. Полнота краёв окна доверяет заголовку;
последовательность номеров выявляет внутренние пропуски и обрезание против
заявленных границ, но не поддельный заголовок или перенумеровку. Независимого
получения и сверки архивов этим шагом не добавлено. Источники без непрерывных
номеров требуют отдельного адаптера полноты; искусственно нумеровать их нельзя.

Лимитки, деривативы, несколько инструментов и недолларовая котировка получают
явный отказ. Прибыльность и допуск к реальным деньгам из работоспособности replay
не следуют. Следующий исследовательский шаг — один кандидат и его полноценный
форвард; расширение очереди лимиток/деривативов остаётся отдельной работой.
