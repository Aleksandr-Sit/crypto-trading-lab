## Что должно заработать

Существующий бот Trader (токен `TELEGRAM_BOT_TOKEN`) принимает команды только от `TELEGRAM_ADMIN_ID`: `/status`, `/halt`, `/resume`, `/promote <id>`, `/retire <id> <причина>`, `/limits`, `/queue`; необратимые — с подтверждением вторым нажатием. Карточки сигналов: на ступени `signal` — кнопки «исполнил / пропустил», на `semi` — «подтвердить / отклонить», на `auto` — сообщение после филла. Утренний отчёт в 09:00 Europe/Samara: P&L за сутки по веткам, переходы по лестнице, ожидающие решения, здоровье источников (данные — через интерфейсы ядра; чего ещё нет — заглушка с честным «н/д»). Outbox с повтором при недоступности Telegram. APScheduler в `worker` с расписанием из `schedule.yaml`; задания регистрируются другими модулями через `register(job)`.

## Критерии приёмки

- [ ] aiogram 3; команды и inline-кнопки; чужой Telegram ID игнорируется молча (тест)
- [ ] `send_card(kind, payload)` для видов: `signal`, `confirm`, `fill`, `transition`, `candidate`, `rebalance`, `allowlist`, `alert`; шаблоны на русском
- [ ] Кнопки сигналов меняют `signals.outcome` через `core.journal`; таймаут (`ttl_s`) → `expired` и сообщение редактируется
- [ ] `/halt` и `/resume` → `core.ladder.halt_all/resume_all` с двойным подтверждением
- [ ] `/promote` работает только `semi→auto` и только от админа; остальные переходы — отказ с пояснением
- [ ] Утренний отчёт по расписанию (`schedule.yaml`, TZ Europe/Samara); одно сообщение + карточки ожидающих решений
- [ ] Outbox: недоставленное хранится, повтор с экспоненциальной задержкой, тест с фейковым Telegram
- [ ] Планировщик: `ops.scheduler.register(job)`; задания идемпотентны при перезапуске; тест регистрации и срабатывания
- [ ] Watchdog-уведомление: если сервис не отвечал 5 минут — `alert` (сам watchdog — тикет 14; здесь — карточка и интерфейс)
