# Интерфейсы проекта

## Правила проекта (для каждого исполнителя)

- **Стек:** Python 3.12, `uv` (зависимости в `pyproject.toml`, лок-файл `uv.lock`), Postgres 16 (через `docker compose`), SQLAlchemy 2 + Alembic, FastAPI + Jinja2 + HTMX, aiogram 3, APScheduler 3, Parquet через `pyarrow` + DuckDB, `pydantic` v2 для конфигов/манифестов, `pytest` + `pytest-asyncio`, `ruff`.
- **Команды:** `uv sync` — установка; `uv run pytest -q` — тесты; `uv run ruff check .` — линт; `docker compose up -d` — запуск; `uv run alembic upgrade head` — миграции; `uv run python -m lab <команда>` — CLI.
- **Тесты не ходят в сеть.** Живые API — только за флагом `LAB_LIVE_TESTS=1`, по умолчанию пропускаются. Всё внешнее — за интерфейсом, в тестах — фейк.
- **Секреты только через `.env` по именам из `.env.example`.** Ни один ключ не в коде, не в тестах, не в логах. Ключи с правом вывода средств отклоняются при старте.
- **Недостающая зависимость = вернуть `BLOCKED` с описанием, не устанавливать что попало.** Добавление зависимости в `pyproject.toml` — допустимо, если она есть в этом файле в разделе «Стек» или в тикете.
- **Не трогать:** `.autopilot/`, `CLAUDE.md` (кроме разрешённого в тикете), чужие зоны.
- **Язык:** код и идентификаторы — английский; тексты для пользователя (Telegram, веб, логи уровня INFO) — русский.
- **Время:** в базе UTC; показ пользователю — `Europe/Samara`.
- **Деньги:** `Decimal`, не float. Валюта учёта — USD.
- **Идентификаторы стратегий:** `<ветка>-<источник>-<слаг>` (`hl-copy-0xabc`, `meme-sol-pumpfun-early-v1`, `nft-mint-priority-v2`).
- **Ветки:** `cex-spot`, `cex-perp`, `dex-perp`, `copy`, `meme`, `nft`, `prediction`, `rh`.
- **Ступени:** `backtest → paper → micro → signal → semi → auto`. **Статусы:** `candidate · measuring · passed · failed · degraded · retired`.
- **Каждое решение стратегии пишется в журнал ДО исхода** (`decided_at`, `inputs_hash`).
- **Ни один ордер не уходит на площадку без `core.risk.check(...) == Allow`.**

### Уточнения после ревью таска 02
- `core.measure.run(..., branch: Branch|str|None=None)` — ветка: явный `branch=` → манифест стратегии → `branch_of_strategy_id(id)` (самое длинное совпадение по `Branch`). `threshold()` даёт `insufficient`, когда критерий не из чего посчитать (нет бенчмарка). `parse_tf`/`TIMEFRAMES` — в `lab.contracts.timeframes`. `pandas` не зависимость. `ttl_s` стратегии — ключ `params["ttl_s"]` манифеста (соглашение, читает ladder).
- **Известный дефект T03 (в concerns, чинить первым):** `risk.check` для `reduce_only` проверяет стопы раньше обхода — закрыть позицию при пробитом стопе нельзя. До фикса worker при `Deny(strategy_stop_*)` на закрывающем ордере должен считать это ошибкой риск-ядра, а не отказом.

- Отклонения/оговорки: `py-clob-client` не в зависимостях (тянет web3/eth-account/python-dotenv — 25 пакетов), клиент чтения и бумаги собран на `httpx` через транспорт из `feeds.chains`; подпись live-ордера грузится лениво, и без пакета ветка честно уходит в «только замер». Robinhood подписывает `cryptography` (уже в дереве), `pynacl` не понадобился. Миграции 0007 не потребовалось: режим ветки живёт в `system_flags`. `config/prediction.yaml` не создавался — параметры стратегии живут в манифесте.

## Из таска 15 — связка замера и `.env`

- `lab.ops.measure` — единственная обёртка, через которую система мерит сама: `make_measure(session_scope, *, store=None, feed_factory=None, root=None) -> measure(strategy_id=, mode=, window=, **kw)`, `run_measure(strategy_id, mode, window, *, session_scope, store=, feed_factory=, root=, **kw) -> Measurement`, `MeasureUnavailable`, `data_root()`, `BENCHMARK_INSTRUMENTS`. Стратегия — `strategies.registry.build(id, params)` (нет кода и ветка бэктестится → `MeasureUnavailable`; форвард-ветка → режим `forward` по сделкам журнала), свечи — `CandleStore` (`LAB_DATA_ROOT`, по умолчанию `data/`), иначе фид площадки (любой отказ фида → `incomplete` с причиной), бенчмарк — BTC той же площадки и tf из хранилища.
- `ops.worker.Worker(..., store=None)`: поле `Worker.measure` — та же обёртка; `jobs()` зовёт `discovery_jobs(measure=self.measure, ...)`, поэтому `remeasure` теперь регистрируется (12 заданий).
- `core.measure.history(session, strategy_id, *, mode=None, limit=5) -> [Measurement]` — сохранённые снимки, свежие первыми.
- `core.registry`: `Candidate.measure_cost`, `measure_cost_of(payload) -> int`, `UNKNOWN_MEASURE_COST=9`; `Registry.candidates()` отдаёт очередь по цене замера (В6), затем по `discovered_at`, `id`.
- `discovery.decisions`: `DecisionResult.measurement` и `DecisionResult.text()`; `candidate_hook(...) -> (ref_id, decision) -> str` (строка для карточки). `bot.TraderBot`: возврат `on_candidate/on_rebalance/on_allowlist` подставляется в карточку (`DecisionHook = (str, str) -> str | None | Awaitable`).
- `lab.config`: `apply_dotenv(path=".env") -> [str]` (выкладывает `.env` в `os.environ`, реальное окружение сильнее — зовётся из `cli.main`), `SERVICE_ENV` (DATABASE_URL, WEB_*, BACKUP_DIR, …) входит в `environment()`. `load_dotenv` срезает хвостовой комментарий вне кавычек.
- CLI: `lab measure run <id> [--mode backtest|paper|forward|micro] [--days N] [--root DIR]`, `lab measure show <id> [--limit N]`; `cli.format_measurement(m, window=None) -> str`. `lab service web` берёт логин/пароль из `.env`; без них — разовый пароль на запуск печатается в лог (веб без авторизации не поднимается).
- `.env.example` копируется без правок: `DATABASE_URL` указывает на локальный Postgres (в compose переменная всё равно подставляется самим compose).
